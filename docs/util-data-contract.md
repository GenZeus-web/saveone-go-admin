# สัญญาข้อมูล น้ำ-ไฟ (UTIL-01)

> ข้อตกลงระหว่าง **ชีตกลาง → Apps Script → Firestore → เว็บ** · ตัวคำนวณฝั่งเว็บ: `js/util-calc.js` (เทสต์ `tests/util-calc.test.js`)
> แผนเต็มอยู่นอก repo (UTIL-plan) · เลขบัญชี/ยอดเงินจริง **ห้ามใส่ในไฟล์นี้** — repo สาธารณะ

## หลัก

1. **เก็บเลขไมล์ ไม่เก็บ "ใช้งาน"** — เว็บคำนวณเองทั้งหมด Apps Script แค่ลงข้อมูล + ส่งขึ้น
2. **1 แถว = 1 การจด** · ห้ามแก้/ลบ — ผิดให้ตั้ง `status = void` แล้วเพิ่มแถวใหม่
3. **ไม่มีคอลัมน์ "รอบ"** — เว็บดูจากเวลาจริง (`ts`) ว่าช่วงไหนตลาดเปิด/ปิด
   จะจดวันละกี่รอบ ตอนไหน ก็ใช้ได้ ต่างแค่ความแม่นของเกณฑ์ตอนปิด (ดูตารางท้ายไฟล์)
4. **วันที่เป็น ค.ศ.** · เวลาไทย `+07:00` เสมอ
5. ตัวคูณ / บาทต่อหน่วย / เกณฑ์ **ไม่อยู่ในชีต** — อยู่ `settings/utility` แก้จากหน้าเว็บ

## วันตลาด

ตลาดเปิดคร่อมเที่ยงคืน (ค่าตั้งต้น 14:00–01:00) → **วันตลาด D = เวลาเปิดวัน D ถึงเวลาเปิดวัน D+1**

- จดตี 1 ครึ่งของวันที่ 2 = ยอดของวันตลาดที่ 1
- ใช้ต่อวัน = ผลต่างเลขไมล์ กระจายตามเวลาที่คาบแต่ละวันตลาด × ตัวคูณที่มีผล**วันนั้น**
- ใบจดกระดาษไม่มีเวลา (`ts` ว่าง) → ถือว่าจด**ตอนเปิด**ของ `read_date` = ได้ผลเท่าการหารจำนวนวันตรงๆ
  (บางนา 18 ก.ย. → 1 ต.ค. สำนักงาน 43 หน่วย = วันตลาด 18–30 ก.ย. วันละ 3.3)

## ชีตกลาง (4 แท็บ)

| แท็บ | ใครเขียน | คอลัมน์ |
|---|---|---|
| `branches` | admin | `branch_code` `name_th` `acc_code` `pin` (ไม่ใช้แล้ว) `active` |
| `staff` (ซ่อน + ล็อก) | admin | `staff_id` `name` `branch_code` `emp_code` `active` |
| `meters` | admin | `meter_id` `branch_code` `type` `location` `account_no` `device_no` `active` `note` |
| `readings` | แอปเท่านั้น | `ts` `read_date` `branch_code` `meter_id` `reading` `meter_reset` `recorder` `source` `status` `note` `photo_id` `staff_id` |
| `bills` | บัญชี | `bill_month` `branch_code` `type` `meter_id` `account_no` `units` `amount_incl_vat` `note` (+ แอปเติม `entered_by` `entered_at` `status`) |

- ทุกแท็บ: **แถว 1 = ชื่อคอลัมน์ภาษาไทย** (ให้คนอ่าน) · **แถว 2 = ชื่อคอลัมน์ข้างบน** (Apps Script อ่านตามนี้ ห้ามแก้) · ข้อมูลเริ่มแถว 3
- `meter_id` = `สาขา-ชนิด-จุด` เช่น `BN-W-TOILET` · `type` = `water` / `elec`
- สาขา: `BG` `BN` · `SS` (ปิด ก.ย. 69 เก็บย้อนหลัง) · `RM` ราม (รหัสชั่วคราว · เปิดสิ้นปี 69 · ฝั่งบัญชียังไม่มีรหัส)
- `account_no` `device_no` `bill_month` เป็น**ข้อความ** (เลข 0 หน้าห้ามหาย)
- `emp_code` (รหัสพนักงาน 6 หลัก = รหัสเข้าแอป) อยู่ในแท็บ `staff` ที่เดียว ไม่ส่งไปหน้าแอป/readings/Firestore · บันทึกเป็น `staff_id` แทน
- `staff`: 1 แถว = 1 คนต่อ 1 สาขา · ลาออก = `active FALSE` (ห้ามลบแถว รายการเก่ายังอ้าง `staff_id`)
- `source` = `app` / `paper` (นำเข้าจากใบจดเดิม)
- `meter_reset` = `TRUE` เมื่อเปลี่ยนมิเตอร์ใหม่ → ช่วงนั้นไม่นับ เลขใหม่เป็นจุดตั้งต้น
- `photo_id` = ID ไฟล์รูปหน้ามิเตอร์ใน Drive (`UTIL รูปมิเตอร์/<สาขา>/<ปี-เดือน>/`) · แอปใส่เอง · ไม่ถ่ายรูป/ใบจดกระดาษ = ว่าง · `setup()` เพิ่มคอลัมน์ให้
- `bill_month` = **เดือนที่บิลออก** · หลักฐาน: บิลน้ำบางนา "ต.ค." ตรงกับใบจด 4 ก.ย. → 4–5 ต.ค. (สำนักงาน 144 vs 142 · ห้องน้ำ 1,083 vs 1,035) → เว็บเลื่อนถอย 1 เดือน (`billMonthOffset: -1`) — **รอบัญชียืนยัน**
- นำเข้าบิลเก่าจาก Excel บัญชี: ปีในไฟล์เป็น 19xx → **+57 ปี**

## Firestore

| เอกสาร | เนื้อหา | Rules |
|---|---|---|
| `data/{BR}_UTIL` | `{csv, metersCsv, rows, branch, ts}` | กฎ `data/` เดิมครอบแล้ว (`"BN_UTIL".split('_')[0]` = `BN`) · ⚠️ ผู้มี `bmBranches` อ่านได้ด้วย (แบบ SEC-08) — ไม่มีเงินในเอกสารนี้ |
| `utilbill/{BR}` | `{csv, rows, branch, ts}` | v3.2.0: admin · หรือสาขาที่ดูแล + `showUtil` + `showUtilMoney` (บล็อก `utilbill/` ใน `docs/firestore-rules/v3.3.0-current.txt`) |
| `settings/utility` | ค่าตั้งค่า (ด้านล่าง) | อ่าน: `hasProfile()` · เขียน: `isAdmin()` · **วางกฎก่อน push** โค้ดที่อ่าน |

`csv` ของ `data/{BR}_UTIL` = แท็บ `readings` ของสาขานั้น ครบทุกแถว**รวม void** (เว็บกรองเอง)
คอลัมน์: `ts,read_date,meter_id,reading,meter_reset,recorder,staff_id,source,status,note,photo_id`
- `ts` เป็น ISO มีโซนเวลา เช่น `2026-10-02T01:30:00+07:00` · ใบจดกระดาษเว้นว่าง

`metersCsv` = แท็บ `meters` ของสาขา **ไม่รวม** `account_no` `device_no`
`csv` ของ `utilbill/{BR}`: `bill_month,meter_id,type,units,amount_incl_vat,note` · **ไม่รวมบิล `void`** (ต่างจาก readings ที่ส่งครบแล้วเว็บกรองเอง)

ขนาด: ~4 มิเตอร์ × 2 รอบ × 365 วัน × ~80 ไบต์ ≈ 230 KB/ปี · เพดานเอกสาร Firestore 1 MB → พอ 3–4 ปี แล้วต้องแยกปี

### `settings/utility`

```js
{
  hours: { default: {open:'14:00', close:'01:00'}, BN: {...} },  // เวลาตลาดต่อสาขาได้
  thresholds: {
    water: { yellow:1.5, red:2, minDiff:10,  streak:3, closedRate:0.5, staleDays:2 },
    elec:  { yellow:1.5, red:2, minDiff:100, streak:3, closedRate:null, staleDays:8 } // ไฟ: ค่าเดา รอข้อมูลจริง · minDiff ต่อวัน (หน้าตั้งค่าแสดง ×7)
  },
  billCheck: { ratio:1.3, lookback:6, minPrev:3, warmup:6, minDiff:{water:50, elec:3000} },   // ตรวจบิล (UTIL-09)
  rates: [ { meter_id, field:'multiplier'|'rate', value, effective_from:'YYYY-MM-DD' } ], // ห้ามแก้ย้อน (ADR 0001)
  edgeMin:15, staleDays:2, baseWeeks:4, baseMinDays:2, billMonthOffset:-1,
  billBase: { n:3, maxAge:4 }   // ช่วงแรกค่ากลางยังไม่พอ → ค่าเฉลี่ยต่อวัน n บิลล่าสุด (UTIL-21 · ไม่มีในหน้าตั้งค่า)
}
```

ช่องที่ไม่ใส่ใช้ค่าตั้งต้นใน `UTIL_DEFAULTS` (เกณฑ์รวมทีละช่อง แก้แค่บางช่องได้)
v3.3.0 (UTIL-16): หน้าตั้งค่า → 💧 เกณฑ์น้ำ-ไฟ เขียน `thresholds` · `baseWeeks` · `baseMinDays` · `billCheck` (merge · ช่องอื่นไม่แตะ) + บันทึกใน `settingsLog` (`util_save`)

## เกณฑ์ (เว็บคำนวณ)

| ชั้น | ตัดสินจาก | ป้าย |
|---|---|---|
| เทียบฐาน | ใช้ต่อวัน vs **ค่ากลาง**ของวันเดียวกันในสัปดาห์ 4 สัปดาห์ก่อน (ข้ามวันแดง · วันปกติ < 2 → ค่าเฉลี่ยต่อวันจาก 3 บิลล่าสุด · ไฟรายสัปดาห์ ×7) | เกิน `red` เท่า **และ** +`minDiff` = 🔴 · เกิน `yellow` เท่า **และ** +`minDiff` = 🟡 |
| ต่อเนื่อง | 🟡 ขึ้นไป ติดกัน `streak` วัน | 🔴 น่าจะรั่ว (`leak`) |
| ตอนปิด | ช่วงจดที่อยู่ใน "ตลาดปิด" **ล้วน** (คลาดได้ `edgeMin` นาที) → หน่วย/ชม. | เกิน `closedRate` = 🔴 · ไฟยังไม่ให้ป้าย |
| ขาดจด | ไม่มีการจดเกิน `staleDays` วัน | เตือน |

- **เส้นแดงจริง = ค่าที่สูงกว่าระหว่าง ฐาน × red กับ ฐาน + minDiff** — มิเตอร์เล็ก (ฐาน 5) ต้องเกิน 15 ไม่ใช่ 10
- **ตัดวันแดงออกจากฐาน** — ไม่ตัด = รั่วนาน 3–4 สัปดาห์ ฐานจะสูงตามจนธงหายเองทั้งที่ยังรั่ว
- ช่วงที่มีเวลาเปิดปน **ไม่ใช้ตัดสินรั่วตอนปิด** (คนใช้จริงจะเป็นธงปลอม)

## แอปกรอก (Apps Script) — `apps-script/util-entry/`

- รหัสสาขา + รหัสพนักงาน 6 หลัก → รู้คน + สาขา → มิเตอร์ของสาขา + เลขครั้งก่อน + log จดล่าสุด → ถ่ายรูปหน้าปัด (**ไม่บังคับ** · สวิตช์ `PHOTO_REQUIRED` ใน Script properties รอ ผอ. ตัดสิน) → ใส่เลข → บันทึก `ts` = เวลา server
- ปฏิเสธ: เลขน้อยกว่าครั้งก่อน (เว้นติ๊ก "เปลี่ยนมิเตอร์ใหม่" + หมายเหตุ) · ไม่มีชื่อคนจด · ไม่มีรูป (เฉพาะเมื่อตั้ง `PHOTO_REQUIRED`)
- รหัสผิด 5 ครั้งใน 15 นาที → ล็อก**เฉพาะสาขานั้น** 15 นาที
- ยกเลิกได้เฉพาะรายการของตัวเองที่ยังไม่มีการจดครั้งถัดไป → `void` + หมายเหตุ (ไม่ลบแถว)
- `pushToFirestore` ทุก 10 นาที (ทริกเกอร์) · สาขาที่ไม่มีแถวไม่เขียน (กันเขียนทับด้วยของว่าง)
- **ไม่รองรับจดย้อนหลัง** — `ts` ต้องเป็นเวลาจดจริง ไม่งั้นตัวคำนวณแบ่งวันตลาดผิด · ลืมจด = admin เพิ่มแถว `paper` เอง
- ไม่ต้องให้พนักงานเลือกรอบ · ไม่คำนวณอะไรทั้งสิ้น
- สาขาใหม่ = เพิ่มแถวใน `branches` + `meters` · ไม่ต้องแก้โค้ดแอป

## ทางเลือกเวลาจด (รอพี่ทุ่งตัดสิน) — ตัวคำนวณรองรับทุกแบบโดยไม่ต้องแก้โค้ด

| แบบ | จด | ใช้ต่อวัน | จับรั่วตอนปิด |
|---|---|---|---|
| ก (แม่นสุด) | 14:00 + 01:00 | ✅ | ✅ ช่วง 01:00→14:00 ปิดล้วน เห็นภายในวัน |
| ข | 14:00 + 23:00 (ช่างคนเดียว) | ✅ | ❌ ช่วง 23:00→14:00 มีเวลาเปิดปน → เหลือแค่เทียบฐาน |
| ค | 14:00 + เช้า (รปภ.) | ✅ | ✅ ช่วงสั้นกว่าแบบ ก |
| ง | 14:00 รอบเดียว | ✅ | ❌ เหลือแค่เทียบฐาน (ช้า 1–3 วัน) |

ยังไม่ทำ: เทียบ "ช่วงกลางคืน 23:00→14:00" กับคืนปกติ (ช่วยแบบ ข) — ทำเมื่อพี่ทุ่งเลือกแบบ ข
